Active Security Features

  • PBKDF2-SHA256 key derivation with high iteration count
  • Unique cryptographic salt per user
  • Timing-safe verifier comparison (crypto.timingSafeEqual)
  • Session stored in SQLite (persistent, not in-memory)
  • HttpOnly, SameSite:Strict session cookie
  • CSRF token protection on all state-changing endpoints
  • Helmet.js security headers (CSP, X-Frame-Options…)
  • Login rate limiting (express-rate-limit)
  • Server-side input validation and sanitisation
  • Parameterized SQLite queries (no SQL injection)
  • Secrets stored in .env (never hard-coded)
  • Audit log for all login and registration events
⚠️

Known Limitations of Graphical Passwords

Shoulder Surfing

An observer watching your screen can see which points you click, making the password easier to steal than a typed password hidden behind dots.

Hotspot Guessing

Users tend to click on visually salient objects (faces, bright lights). Attackers can exploit this predictability by testing popular regions first.

Grid Tolerance

A coarse grid (10×10 = 100 cells) balances usability with security. A very fine grid causes login failures from slight mouse drift.

No Multi-Factor

This system uses graphical password alone. In production, combining it with a second factor (OTP, hardware key) would significantly raise security.
